# Design decisions V1

1. Брендовое направление: **AXION**.
2. Основной визуальный стиль: тёмный технологичный интерфейс с emerald / teal акцентами.
3. Главная AXION V2 — принятый visual reference общего shell/sidebar; файл `01_home_axion_v2_candidate.png` сохраняет историческое имя, но имеет статус VISUAL LOCK.
4. Основной пользовательский поток: `Данные → Признаки → Алгоритм → Проверка качества → Результат`.
5. Экраны в `docs/design/screens/` считаются рабочими утверждёнными референсами первой сборки.
6. Макеты задают композицию, визуальную иерархию и характер интерфейса; backend-контракты остаются источником истины для данных и поведения.
7. Мелкие визуальные правки допускаются после реального просмотра в приложении и подтверждения владельцем.
8. Не начинать новую UI-реализацию без проверки соответствующего design reference.
9. Не выбирать самостоятельно порядок экранов, новую визуальную концепцию или другую модель разработки без согласования с владельцем.
10. Quality V1: visual lock — `docs/design/screens/new-analysis/05_quality_v1.png`; экран является контрольной точкой перед full experiment, а не второй формой обязательных настроек.
11. Quality preflight запускается автоматически; пользовательская primary CTA после PASS — **«Начать обучение»**. Термин `smoke` остаётся техническим и не используется как quality verdict.
12. После старта шаг 4 показывает реальный progress full experiment на том же экране; fake percentages/ETA запрещены, затем открывается `Результат`.
13. Result V2: приняты visual lock `02_result_model_overview_v2.png`, `03_threshold_explorer_v1.png`, `04_result_objects_v2.png`.
14. Threshold Explorer использует OOF scores; изменение threshold не переобучает модель и меняет только derived classification/metrics.
15. Result semantic accents: FN — restrained pink/red, FP — amber, TP — cyan/teal, TN — muted neutral; target fact и threshold position остаются отдельными смыслами.
16. В Objects marker matrix фиксирована: TP=`● cyan Да`, FN=`● pink/red Да`, TN=`○ muted Нет`, FP=`○ amber Нет`.
17. Objects table — scrollable/virtualizable analytical view со sticky header; classic numbered pagination не является canonical UX.
18. Fold в Objects остаётся read-only OOF provenance с tooltip; точные Result backend/public contracts определяются отдельно Architect и не выводятся из PNG.
19. Профессиональный принцип AXION: скрывать сложность можно, удалять реально поддерживаемую аналитическую возможность — нельзя; advanced controls допустимо убирать на второй уровень UI.
20. Object Detail показывает basic OOF result сразу; Local Explanation запускается автоматически отдельным request и не блокирует основной экран.
21. Для любой модели, доступной как полноценная модель AXION, обязателен validated путь `prediction → Local Explanation → Result Interpreter`; UI не ветвится по model family.
22. External LLM не запускается автоматически: после готового Local Explanation пользователь явно вызывает «Сформировать объяснение», если policy/provider capability доступна.
23. Прежний `GBDT Mean SHAP = UNSUPPORTED` superseded Universal Model Explainability V1: целевая semantics — validated probability-space ensemble explanation с fail-closed reconstruction checks.
24. Objects screen: control «Диапазон оценки модели» обязателен — dual-handle slider 0,00–1,00 с явными min/max values; он фильтрует OOF object list через `min_score`/`max_score`, не меняя threshold или score. Если текущий visual reference его не показывает, это visual omission и control должен быть возвращён в следующей revision.
25. Object Detail V1: visual lock — `docs/design/screens/result/05_result_object_detail_v1.png`; экран показывает один OOF-объект, deterministic outcome explanation, Local Explanation READY в режиме «Кратко», role-aware LLM entry по явному действию и collapsed object/technical details.
26. Object Detail LLM V1: visual lock — `docs/design/screens/result/06_result_object_detail_llm_v1.png`; LLM READY остаётся на том же detail screen, показывает четыре блока «Краткий вывод / Что увеличило оценку / Что уменьшило оценку / Что важно учитывать», допускает «Сформировать заново» и обязан использовать только validated Local Explanation evidence текущего объекта. «Начальная оценка модели» — SHAP reference point с поясняющим tooltip, не threshold и не business risk.
27. Connect Algorithm V1: visual lock — `docs/design/screens/algorithm/01_connect_algorithm_v1.png`; подключается trusted algorithm/ModelPlugin, не обученная ModelVersion. Один flow имеет две точки входа: `Новый анализ → Алгоритм` и `Модели`; после success/cancel возврат идёт в исходный контекст.
28. Connect Algorithm V1: editable «Название в AXION» — только display alias; trusted algorithm ID/version/provider identity остаются read-only source of truth. Dataset, feature count, quality metrics и trained-model facts на этом экране не показываются.
29. Models Hub V1: visual lock — `docs/design/screens/models/01_models_hub_v1.png`; раздел различает Algorithm/ModelPlugin и конкретные обученные ModelVersion. Общий список показывает сохранённые ModelVersion, а вкладка «Алгоритмы» даёт вход в историю обучений конкретного алгоритма.
30. Algorithm Detail V1: visual lock — `02_algorithm_detail_v1.png`; экран алгоритма показывает все сохранённые ModelVersion этого алгоритма с dataset, feature count, training date и OOF-labelled metrics. Это каталог фактов, а не ranking/winner selection.
31. Metric Highlight V1: optional toggle, default OFF. Highlight state — `02_algorithm_detail_highlight_v1.png`; OOF Gini / ROC-AUC / PR-AUC сравниваются отдельно по колонкам относительно текущего filtered list. Подсветка не является рейтингом, quality verdict или final-test evidence.
32. ModelVersion Detail V1: visual lock — `docs/design/screens/models/03_model_version_detail_v1.png`; detail показывает одну immutable saved ModelVersion. Основные действия: использовать для прогноза, создать новый запуск на основе модели, открыть сохранённые результаты. Новый запуск не перезаписывает текущую ModelVersion.
33. ModelVersion Detail V1: отдельный дублирующий «Обзор модели» не нужен; quick summary содержит dataset / feature count / training date / OOF Gini, полный набор метрик живёт только в «Качество модели (OOF)», параметры и техническая provenance по умолчанию collapsed.
34. AXION action-copy: основные кнопки формулируются максимально коротко и по-человечески, когда контекст уже однозначен; иконка несёт часть смысла действия. Пример: `▶ Анализ` вместо длинного технического CTA на экране применения готовой модели. Пояснение добавляется только там, где без него пользователь может ошибиться. Принятые PNG не перерисовываются только ради сокращения текста: при реализации допустимо точечно упростить подписи, сохранив смысл действия и общий visual style.
35. Saved Model Inference V1: visual lock — `docs/design/screens/models/04_saved_model_inference_v1.png`; сохранённая ModelVersion применяется к новым данным без retraining. Экран обязан различать dataset обучения модели и новый inference dataset, проверять trusted feature binding/types/order, допускать отсутствие target и не считать лишние колонки model inputs.
36. Saved Model Inference V1: primary action — короткий `▶ Анализ`; это общий action-copy принцип AXION, а не изменение backend semantics. На экране показывается `Признаков модели`, а не абстрактное `Входных признаков`.
37. Saved Model Inference Result V1: успешный targetless inference автоматически создаёт immutable persisted Result (`ModelVersion + input dataset identity + object identities + scores`); threshold и UI filters не входят в immutable Result и не меняют его evidence.
38. Saved Model Inference Result V1: `Изменить порог` работает inline и меняет только above/below derived view, counts, filters/sorting; не retrain/recalculate и не создаёт новый Result. Без target запрещены TP/TN/FP/FN и quality metrics.
39. Saved Model Inference Result V1: initial threshold без saved configuration = technical `0.50`; OOF diagnostic threshold автоматически не переносится. V1 допускает одну mutable saved view configuration на Result.
40. Saved Model Inference Result V1: primary action `Сохранить конфигурацию` сохраняет threshold, score range, `Все/Выше/Ниже`, sort и identifier search для текущего Result; при повторном открытии они восстанавливаются. Повторное сохранение обновляет ту же конфигурацию, named scenario history не создаётся.
41. Saved Model Inference Result V1: `Сбросить настройки` находится в `⋯` и показывается только при наличии saved configuration; удаляет только view configuration и возвращает defaults `0.50 / 0.00–1.00 / Все / SCORE_DESC / пустой поиск`, не затрагивая immutable Result/scores.
42. Saved Model Inference Result V1: `docs/design/screens/models/05_saved_model_inference_result_v1.png` — accepted VISUAL LOCK. Показанный `0.37` трактуется как пример изменённой/сохранённой view configuration; чистый Result без saved configuration открывается с technical default `0.50`.
43. Result V2 Global OOF SHAP: `docs/design/screens/result/07_result_global_oof_shap_v1.png` — accepted VISUAL LOCK. Экран показывает `mean(abs(local SHAP))` по OOF population, без направления ↑/↓, процентов, causal/business semantics; technical output space/provider/method приходят из backend provenance.
44. Result V2 Object Detail Loading: `docs/design/screens/result/08_result_object_detail_explanation_loading_v1.png` — accepted VISUAL LOCK. Basic OOF result доступен сразу, Local Explanation рассчитывается отдельно, LLM action disabled до validated evidence. Для новых экранов визуальное направление — спокойный Graphite + Emerald; neon cyan не является обязательным brand lock.
45. Result V2 Object Detail Error: `docs/design/screens/result/09_result_object_detail_explanation_error_v1.png` — accepted VISUAL LOCK. Local Explanation failure не уничтожает basic OOF result; retry повторяет только explanation, final/refit fallback запрещён, LLM остаётся disabled до validated Local Explanation.
46. Result V2 Object Detail Detailed: `docs/design/screens/result/10_result_object_detail_explanation_detailed_v1.png` — accepted VISUAL LOCK режима `Подробно` того же Object Detail. Показываются SHAP reference/base value, итоговый explained output, waterfall, `Остальные признаки` и полный список вкладов; method/output space/provider берутся из backend provenance.
47. Result V2 Result Interpreter Loading: `docs/design/screens/result/11_result_object_detail_llm_loading_v1.png` — accepted VISUAL LOCK. OOF/SHAP evidence остаётся полностью доступным; loading относится только к текстовой интерпретации выбранной роли, без fake progress/ETA и без параллельного повторного запроса для той же роли.
48. Result V2 Result Interpreter Error: `docs/design/screens/result/12_result_object_detail_llm_error_v1.png` — accepted VISUAL LOCK. Ошибка интерпретатора локальна, не меняет prediction/SHAP/threshold; retry использует уже validated Local Explanation, technical reason остаётся вторичным.
49. History V1: отдельная domain-сущность `Project` не вводится. Sidebar canonical label — `История`; одна запись каталога = один завершённый immutable `ExperimentArtifact` / experiment run.
50. History V1 visual lock — `docs/design/screens/history/01_analysis_history_v1.png`. Экран показывает дату, dataset, algorithm, feature count, OOF/folds, Gini, access mode и действие открытия сохранённого результата.
51. History V1 различает `FULL_RESULT_V2` и `LEGACY_SUMMARY_ONLY`: V3 открывает существующий Result V2; legacy показывает только реально сохранённую immutable сводку без реконструкции Objects/SHAP.
52. History read boundary: `AnalysisHistoryService.list()` + `detail()`. UI не сканирует filesystem; дата берётся из `ExperimentResult.created_at`, а не mtime.
53. Открытие History не мутирует текущую analysis session. ModelVersion catalog и targetless inference history остаются только в `Модели`.
54. Settings V1: `docs/design/screens/settings/01_settings_v1.png` — accepted VISUAL LOCK основного collapsed state; `02_settings_privacy_expanded_v1.png` — accepted expanded privacy state.
55. Settings V1 содержит две группы: global interface preference и Result Interpreter integration controls. Scientific Analysis/Algorithm/Quality/Result/Inference parameters не переносятся в global Settings.
56. До отдельного authentication/users contract AXION не показывает fake avatar/name/role/profile/login UI; Settings persistence V1 трактуется как local application preferences, а не account/per-user database.
57. Result Interpreter Settings: user enable может только сузить deployment policy; provider read-only при одном trusted provider; model выбирается только из trusted catalog; default role — initial UI preference; credentials управляются только через secure credential boundary; external-data policy read-only.
58. Connection check — explicit real synthetic provider request без client/model data; `Соединение работает` может быть transient state, persisted `Последняя проверка...` не обещается без отдельного contract.
59. Canonical artifact/model/history storage остаётся application-managed; Settings V1 не содержит переключатель внутренней папки. External export — отдельный будущий flow.
60. Settings implementation order: `SET-BE1 — Local Preferences + Interpreter Settings` → `SET-BE2 — Secure Credentials + Connection Check` → `SET-UI1`.
